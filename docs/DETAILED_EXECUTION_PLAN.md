# Personal Assistant Phase 2 - 详细分阶段执行计划

## 执行原则

1. **分阶段推进**：严格按照阶段顺序执行
2. **三次检查机制**：每个阶段完成后进行 3 次验证检查
3. **先规划后执行**：每个阶段先做详细分析，再执行
4. **保持后向兼容**：每个阶段都要确保不破坏现有功能

---

## 🎯 阶段 0: 深度分析与准备 (30 mins)

### 目标
全面分析现有代码结构，识别依赖关系，为重构做准备

### 步骤
1. **1.1 代码结构分析** (10 mins)
   - 分析 `src/agent/` 目录下所有文件的职责
   - 绘制模块依赖关系图
   - 识别高耦合点

2. **1.2 测试覆盖分析** (10 mins)
   - 分析现有测试覆盖范围
   - 识别测试空白区域
   - 确定重构测试策略

3. **1.3 重构风险评估** (10 mins)
   - 评估重构范围风险
   - 确定最小可行重构路径
   - 建立回滚方案

### 验收标准
- [ ] 完成模块依赖关系分析报告
- [ ] 确定具体的重构路径
- [ ] 完成风险评估文档

## 🎯 阶段 1: Agent 模块分层架构重构 - 基础设施层 (1 小时)

### 目标
创建新的目录结构，迁移基础设施层代码

### 步骤
1. **1.1 创建新目录结构** (15 mins)
   - 创建 `domain/`, `application/`, `infrastructure/`, `interfaces/` 目录
   - 创建子目录 `models/`, `services/`, `repositories/`, `use-cases/`
   - 验证目录结构符合架构设计

2. **1.2 迁移类型定义** (15 mins)
   - 将相关类型定义迁移到 `domain/models/`
   - 更新导入路径
   - 保持类型兼容性

3. **1.3 迁移基础设施代码** (30 mins)
   - 移动 LLM 相关代码到 `infrastructure/llm/`
   - 移动存储相关代码到 `infrastructure/storage/`
   - 更新所有导入路径

### 三次检查
**检查点 1** - 目录结构和文件存在性
- [ ] 所有新目录已创建
- [ ] 类型文件已迁移
- [ ] 基础设施文件已迁移

**检查点 2** - TypeScript 编译检查
- [ ] 运行 `npm run build` - 没有错误
- [ ] 没有导入路径错误
- [ ] 类型检查通过

**检查点 3** - 测试基本通过
- [ ] 运行 `npm run test`
- [ ] 至少 90% 测试通过
- [ ] 核心功能测试通过

## 🎯 阶段 2: Agent 模块分层架构重构 - 领域层 (1.5 小时)

### 目标
迁移纯业务逻辑到领域层，保持纯粹性

### 步骤
1. **2.1 提取领域模型** (30 mins)
   - 识别领域实体和值对象
   - 创建 `domain/models/` 下的文件
   - 确保不包含基础设施依赖

2. **2.2 实现领域服务** (30 mins)
   - 将业务逻辑迁移到 `domain/services/`
   - 实现纯函数，无副作用
   - 添加完整的单元测试

3. **2.3 定义仓储接口** (30 mins)
   - 在 `domain/repositories/` 中定义接口
   - 确保接口只依赖领域模型
   - 不依赖具体实现

### 三次检查
**检查点 1** - 领域层纯净度
- [ ] 领域模型没有外部依赖
- [ ] 领域服务是纯函数
- [ ] 仓储接口正确定义

**检查点 2** - TypeScript 编译检查
- [ ] 运行 `npm run build`
- [ ] 所有导入路径正确
- [ ] 类型定义完整

**检查点 3** - 测试覆盖验证
- [ ] 新增的领域层有完整测试
- [ ] 所有现有测试通过
- [ ] 测试覆盖率 > 80%
